Context-preserving regional inference for Hecate

Oisin McGlone · 26 October 2026
ImplementationMeasurementsReproductionPrior work

Summary

The regional interface for the standalone Hecate runtime accepts a parent scan and an output rectangle. It retains the contributing tile windows, their original batch groups and overlap weights, while allocating blending arrays only for the requested output. The implementation makes regional requests reproducible against the parent run without requiring the caller to construct an aligned context crop.

In the repeated comparison, the regional implementation used 16–36× less temporary blending storage than aligned cropping for small requests. Both methods produced exactly the same saved predictions as full-field inference and had similar runtimes. Across all 11 requests and three repetitions, all 106,668 regional values matched their full-field references.

The practical contribution is a tested Python API and command-line implementation for local inspection or annotation workflows. It avoids recomputing the entire supplied field when only a small region is needed, and keeps the temporary output arrays proportional to that region. The result concerns execution efficiency and output consistency; ink-detection accuracy was not improved or evaluated in this study.

Three measured runs per method; model loading and warmup excluded. “Changed” means disagreement with the corresponding saved uint8 output of the parent-field run. Temporary blending storage consists of the numerator and weight arrays, backed by memory-mapped files; it is not total model RAM.

The regional call reduces the example’s blending arrays from 1,152 KiB to 32 KiB relative to the aligned crop. Both evaluate four windows. The measured advantage over that comparator is storage and automatic context handling; a runtime advantage over aligned cropping is not established.

Implementation

The supplied hecate_roi.py exposes schedule(), predict_roi() and a CLI accepting an output rectangle in the parent array’s coordinates. The scheduler constructs the parent field’s tile grid, including boundary tiles, and retains complete original batch groups whenever a member contributes to the request. The predictor applies the original overlap weights and accumulates only the intersecting output.

Preserving the parent grid matters because cropping the input changes the context seen by the model. In the PHerc0009B example, a tight input crop changes 3,944 of 4,096 saved output values. Merely adding a border is insufficient unless the contributing windows retain their original alignment and execution context.

Validation

The repeated study comprises 11 requests from three previously examined physical fields: PHerc0841, PHerc0009B and PHerc0500P2. Two central requests use 2.4 µm inputs; edge, central and large requests on each of the three fields use 9.6 µm inputs. Each method ran three times with execution order rotated. The environment was a Mac M2 Pro, CPU float32, four threads and fixed weights, with one excluded warmup per worker.

All regional and aligned-crop outputs matched the saved full-field references. The five central requests required four windows instead of nine; their median full/regional runtime ratios were 2.20–2.43. Across small requests, median regional/aligned-crop time ratios were 0.965–1.018. Large requests required all nine windows and were slightly slower than full-field execution.

Timing ratios are calculated within each repetition and then summarised by their median; the example table above gives medians of elapsed times separately. Coarse requests share the full-field timing within each repeat. The detailed viewer includes every trial and observed range.

The package retains all completed runs, including the slow first PHerc0009B full-field trial. A power interruption terminated an incomplete attempt before any prediction was saved; its log and the unchanged-protocol continuation are included. The earlier matrix adds 541,184 matching regional values across eight 2D/3D, direction and batch configurations.

These tests establish equivalence to a software reference on bounded supplied fields. They do not measure ink accuracy, full-scroll throughput or annotation time. GPU performance, independent hardware replication and use in a community application remain unverified. The 16–36× storage reduction applies to the blending arrays; the model’s own memory requirement is separate.

Use and reproduce

To check the supplied results with Python’s standard library, run from this package directory:

python3 -I -S evidence/verify_repeats.py --package evidence

This verifies saved files, output equality and the arithmetic of the recorded measurements. Fresh inference requires the pinned environment and Hecate checkpoint described in the reproduction instructions. From the evidence/ directory, a regional request is:

python src/hecate_roi.py \
  --runtime data/paired-resolution-audit/hecate-runtime-pinned.py \
  --checkpoint models/hecate_2.4um.pth \
  --input inputs/PHerc0009B.npy --spacing-um 2.4 \
  --roi 144 144 208 208 --output my-region.png

Coordinates are half-open X0 Y0 X1 Y1 bounds in the supplied parent array. The input must retain its original context. The five-worker protocol reproduces the repeated comparison; checkpoints are obtained separately and checked against the recorded hashes.

Prior work

The global-grid principle is established prior work. TAUIL Abd Elilah’s villa PR #1247 preserves the full-volume patch grid for bounded surface inference. ArcheyChen’s Hecate runner provides an existing throughput optimisation, and the released Hecate runtime supplies the model, normalisation and blending convention used here.

This implementation adds a regional interface for Hecate, preservation of original batch and depth behaviour, output-bounded accumulation, and a repeatable comparison against aligned context cropping. It does not claim the invention of context preservation, superiority to existing GPU runners, or recovery of previously unread text.
